description: trace-dispatcher's per-namespace ConfBackend is a total override of the default backend list, not an addition - any code that "adds" Forwarder to a namespace's backends by writing an explicit backends list silently drops whatever defaultCardanoConfig would otherwise have set for that namespace (e.g. Stdout MachineFormat)

`cardano-node/src/Cardano/Node/Tracing/DefaultTraceConfig.hs`'s `defaultCardanoConfig` sets the root namespace (`[]`/`""`) backends to `[Stdout MachineFormat, EKGBackend]`. Any node config that explicitly sets a `ConfBackend`/`"backends"` list for that same namespace (even just to turn on `Forwarder`) *replaces* this default for that namespace rather than adding to it - confirmed via `trace-dispatcher/doc/config.json`, `cardano-node/test/.../NewTracing/data/{good,bad}Config.yaml` (which all explicitly re-list `Stdout MachineFormat` alongside `Forwarder`/`EKGBackend` precisely because omitting it would drop JSON stdout).

This matters because `cardano-testnet`'s `findLastSlot` helper (`cardano-testnet/test/cardano-testnet-test/Cardano/Testnet/Test/Node/Shutdown.hs:286-292`) JSON-decodes node stdout line by line - it depends on `Stdout MachineFormat` being present. Any feature that writes an explicit backends list for the root namespace (e.g. to enable `Forwarder` for cardano-tracer support) must include `"Stdout MachineFormat"` in that list, not just `Forwarder`/`EKGBackend`, or stdout-JSON-parsing test helpers silently break if ever combined with that feature.

Found as a recurring bug across two rounds of IntersectMBO/cardano-node PR #6710 ("Add prometheus support to cardano-testnet"): v1's `Testnet.Defaults.traceOptionsForwarding` set `backends: [Forwarder, EKGBackend]` (no Stdout at all); v2 changed it to `[Forwarder, EKGBackend, "Stdout HumanFormatColoured"]` (human-readable coloured text) — cosmetically better (something now shows on stdout) but still not `Stdout MachineFormat`, so the JSON-stdout-parsing assumption is still broken whenever `--enable-tracer` is combined with a test/tool that parses node stdout as JSON. Not an active CI regression in that PR (no test combines both), but a latent landmine.

**STILL BROKEN at round 3 (head 2e3bc9f8, 2026-10-05)**, despite the PR author adding a whole merge/dedup machinery in response to carbolymer's "keep Stdout MachineFormat" correction, and despite that GitHub review thread being marked `resolved: true`. Root cause, confirmed by code trace: `Testnet.Defaults.defaultYamlHardforkViaConfig` writes every testnet node's on-disk `TraceOptions` key as `Aeson.object mempty` (a literal empty object — comment says "empty map = use all defaults"). `Start/Cardano.hs`'s `enableTraceForwarding` merges via `KeyMap.insertWith mergeTraceOptions "TraceOptions" Defaults.traceOptionsForwarding config`, which calls `mergeTraceOptions (Object forwarding) (Object existing)` = `KeyMap.unionWith mergeNamespace forwarding existing`. **`Data.Aeson.KeyMap.unionWith` (same semantics as `Data.Map.unionWith`) only invokes the merge function for keys present in BOTH maps; a key present in only one map is passed through unchanged.** Since `existing`'s `TraceOptions` object has no `""` (root namespace) key at all, `mergeNamespace`/`copyIfMissing`/`mergeBackends` never fire — the root namespace in the final config is `forwarding`'s object verbatim, i.e. exactly `Defaults.traceOptionsForwarding`'s literal `["Forwarder","EKGBackend","Stdout HumanFormatColoured"]`. **The entire careful-merge rewrite is dead code on the default/mainline path**; it would only ever activate if some other code path (e.g. a future `StartFromEnv` custom node config) populated a real root-namespace entry before this runs. Fix: change the literal third backend entry to `"Stdout MachineFormat"` (cosmetic coloured-stdout is not worth breaking JSON parsers for), or stop writing an empty placeholder `TraceOptions` in `defaultYamlConfig` so the merge path actually has something to merge against.

General lesson for any future review of Aeson/Yaml `KeyMap`/`Map` based "merge configs" code in this codebase: **always check whether `unionWith`'s two sides actually share the key in the normal/default case** — a `mempty`/placeholder default on one side silently defeats arbitrarily careful merge logic, and nothing type-checks to catch it.
